# Versão e histórico de mudanças — plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** O rodapé mostra a versão do site, a página `/novidades` mostra o histórico, e `npm run versao` lança uma versão nova a partir dos commits.

**Architecture:** As regras (separar commits por tipo, decidir o número, montar a entrada) ficam em `lib/versao.ts`, sem efeitos colaterais e com testes. O script `scripts/versao.ts` (rodado pelo Node 26, que executa TypeScript direto) lê o Git e grava `package.json`, `package-lock.json` e `lib/versoes.json`. O site importa `lib/versoes.json` e a versão do `package.json`.

**Tech Stack:** Next.js 16 (App Router), TypeScript, Tailwind 4, Vitest, Node 26 (type stripping), Git.

**Spec:** `docs/superpowers/specs/2026-11-14-versao-design.md`

## Global Constraints

- Textos e nomes em português (pt-BR). Títulos das listas: "Novidades" e "Correções e melhorias". Link do rodapé: "Novidades". Formato no rodapé: `v1.0.0`.
- Regra do número: algum `feat:` → sobe o do meio e zera o último (1.0.3 → 1.1.0); senão algum `fix:` ou `perf:` → sobe o último; senão não há versão nova. `--maior` sobe o primeiro e zera os outros.
- `feat:` → "Novidades"; `fix:` e `perf:` → "Correções e melhorias"; `test:`, `docs:`, `refactor:`, `chore:` e qualquer outro tipo não aparecem.
- Texto do item: assunto do commit sem o prefixo (`tipo:` ou `tipo(escopo):`), com a primeira letra maiúscula.
- Data no JSON em ISO (`2026-11-14`); na página, em formato brasileiro (`14/11/2026`).
- O script não faz push. Commit da versão: `chore: versão X.Y.Z` + linha `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Tag anotada `vX.Y.Z`.
- Sem dependências novas.
- Testes pelo PowerShell a partir de `C:\` maiúsculo: `Set-Location "C:\projetos\catalogo-filmes"; npx vitest run`. Lint `npm run lint`, tipos `npx tsc --noEmit`, build `npm run build`.
- Um passo de cada vez: ao fim de cada tarefa, explique ao usuário o que foi feito e espere o OK.
- Branch `feat/versao`. Ao terminar um item da checklist, marque-o num commit `docs: checklist` separado.

## Review Focus

- **Commit com escopo**, como `feat(tmdb): listar séries`: o prefixo inteiro sai do texto → teste em `classificarCommits` (Task 1).
- **Assunto sem prefixo** (um merge, ou um texto livre): ignorado, não quebra → teste (Task 1).
- **O próprio commit `chore: versão 1.0.0`** entre os commits lidos: nunca entra no histórico → coberto por "chore não aparece" (Task 1).
- **Rodar com mudanças não commitadas**: o script recusa, sem gravar nada → passo de verificação (Task 2).
- **Nada para lançar** (só `docs:` e `test:`): o script avisa e sai sem commit nem tag → passo de verificação (Task 2).

### Task 1: Regras da versão

**Files:**
- Create: `lib/versao.ts`
- Test: `lib/versao.test.ts`

**Interfaces:**
- Produces:
  - `type Versao = { versao: string; data: string; novidades: string[]; correcoes: string[] }`
  - `classificarCommits(assuntos: string[]): { novidades: string[]; correcoes: string[] }` (mantém a ordem recebida)
  - `proximaVersao(atual: string, mudancas: { novidades: string[]; correcoes: string[] }, maior?: boolean): string | null`
  - `lib/versao.ts` não importa nada com `@/` (o script o importa por caminho relativo).

- [ ] **Step 1: Testes que falham** em `lib/versao.test.ts`:
  - `classificarCommits(["feat: fileira Para você", "fix: pôster quebrado", "perf: conexão cedo", "test: mais testes", "docs: checklist", "chore: versão 1.0.0"])` → `{ novidades: ["Fileira Para você"], correcoes: ["Pôster quebrado", "Conexão cedo"] }`.
  - Escopo: `classificarCommits(["feat(tmdb): listar séries"])` → `novidades: ["Listar séries"]`.
  - Sem prefixo: `classificarCommits(["Merge branch x", "texto livre"])` → as duas listas vazias.
  - `proximaVersao("1.0.3", { novidades: ["a"], correcoes: [] })` → `"1.1.0"`.
  - `proximaVersao("1.1.0", { novidades: [], correcoes: ["b"] })` → `"1.1.1"`.
  - `proximaVersao("1.1.1", { novidades: [], correcoes: [] })` → `null`.
  - `proximaVersao("1.4.2", { novidades: [], correcoes: ["b"] }, true)` → `"2.0.0"`.
- [ ] **Step 2:** `npx vitest run lib/versao.test.ts` → falha (módulo não existe).
- [ ] **Step 3:** Implementar `lib/versao.ts` com as assinaturas acima. O prefixo é `^(\w+)(\([^)]*\))?:\s*`.
- [ ] **Step 4:** `npx vitest run lib/versao.test.ts` → passa; suíte completa, `npx tsc --noEmit` e `npm run lint` limpos.
- [ ] **Step 5: Commit** `feat: regras da versão a partir dos commits` (`lib/versao.ts lib/versao.test.ts`).

### Task 2: O comando `npm run versao`

**Files:**
- Create: `scripts/versao.ts`, `lib/versoes.json` (conteúdo `[]` se ainda não existir)
- Modify: `package.json` (script `"versao": "node scripts/versao.ts"`), `tsconfig.json` (`"allowImportingTsExtensions": true`, se o `tsc` reclamar do import `../lib/versao.ts`)

**Interfaces:**
- Consumes: `classificarCommits`, `proximaVersao`, `Versao` (Task 1), importados como `../lib/versao.ts`.
- Produces: `lib/versoes.json` — lista de `Versao`, a mais nova primeiro.

- [ ] **Step 1: Implementar `scripts/versao.ts`**, chamando o Git com `execFileSync` (sem shell):
  1. `git status --porcelain` não vazio → mensagem "Há mudanças não commitadas. Faça o commit antes de lançar a versão." e sai com código 1.
  2. Última tag: `git describe --tags --abbrev=0 --match "v*"`. Sem tag → mensagem "Nenhuma versão lançada ainda: crie a v1.0.0 primeiro." e código 1.
  3. Assuntos: `git log <tag>..HEAD --format=%s`; `classificarCommits`; `proximaVersao(versão do package.json, ..., process.argv.includes("--maior"))`.
  4. `null` → "Nada para lançar desde <tag>: só bastidores (testes, documentação, organização)." e código 0, sem gravar.
  5. Com `--simular`: imprime a versão nova e as duas listas e sai, sem gravar.
  6. Senão: `npm version <nova> --no-git-tag-version` (atualiza `package.json` e `package-lock.json`); acrescenta `{ versao, data: hoje em ISO local, novidades, correcoes }` no **início** de `lib/versoes.json` (JSON com 2 espaços e quebra de linha final); `git add` dos três arquivos; commit `chore: versão X.Y.Z` com a linha Co-Authored-By; `git tag -a vX.Y.Z -m "Versão X.Y.Z"`; imprime "Versão X.Y.Z criada. Para publicar: git push origin main --follow-tags".
- [ ] **Step 2: Verificar** (sem tag ainda, então numa cópia descartável): `git clone . <pasta no scratchpad>`, nela `git tag v1.0.0 HEAD~3` e rodar:
  - `node scripts/versao.ts --simular` → mostra uma versão e as listas, e `git status` continua limpo.
  - Criar um arquivo solto e rodar `node scripts/versao.ts` → recusa com a mensagem de mudanças não commitadas.
  - Remover o arquivo e rodar `node scripts/versao.ts` → cria o commit e a tag; `git log -1` e `git tag` mostram os dois; `lib/versoes.json` tem a entrada no início.
  - Logo depois, de novo → "Nada para lançar".
  - Apagar a cópia.
- [ ] **Step 3:** `npx tsc --noEmit`, `npm run lint` e a suíte → limpos.
- [ ] **Step 4: Commit** `feat: comando npm run versao` (`scripts/versao.ts package.json lib/versoes.json` e `tsconfig.json` se mudou).
